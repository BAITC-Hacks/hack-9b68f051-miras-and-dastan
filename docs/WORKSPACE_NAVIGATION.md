# Навигация после редизайна

В общей оболочке доступны шесть рабочих разделов:

- **Обзор** (`#overview`) — показатели текущего расчёта и приоритетные позиции.
- **Рекомендации** (`#recommendations`) — весь ассортимент, фильтры, выбор позиций и карточка с локальным разбором.
- **Проверка на истории** (`#backtest`) — сравнение прогнозов на недельной истории выбранного SKU.
- **Сценарии** (`#scenarios`) — спрос, задержка, уровень сервиса и бюджет; сравнение с базой.
- **Черновики заказов** (`#drafts`) — выбранные допустимые позиции, сгруппированные по поставщикам, CSV и текст письма.
- **Данные** (`#data`) — выбор демо/импорта, источник и качество истории.

Набор данных, применённый сценарий, поиск и выбор товаров сохраняются при переходах. Загрузка нового набора сбрасывает фильтры и сценарий. Работают кнопки браузера «Назад» и «Вперёд». Ссылки прежнего интерфейса совместимы: `#api` открывает рекомендации, `#orders` — черновики, `#start` — выбор данных. Без загруженного набора показывается начальное состояние внутри оболочки.

Сессия хранится только в памяти вкладки: после перезагрузки данные нужно загрузить снова. Коммерческие данные не сохраняются в localStorage. При изменении расчёта существующий черновик сохраняет старые количества и требует явного пересмотра. Результаты исторической проверки экспортируйте перед выходом: при повторном входе сравнение запускается заново.

## Проверка на истории

Компонент `HistoryPanel` передаёт текущий `Dataset` в адаптер `fromStockPilotDataset` и подключает существующие функции `lib/analytics` через `createStockPilotStrategy`. Прогноз рассчитывается только по завершённым прошлым неделям; правила закупки одинаковы у обеих стратегий. `BacktestPanel` показывает настоящий источник данных и фактические названия стратегий. Это сравнение прогнозов, а не проверка бюджета и выбора поставщика всей системы.

Начальный запас задан отдельно как редактируемое допущение. Сегодняшние остатки и товары в пути не подставляются в исторический старт. При наличии поставщика его текущие сроки, MOQ, упаковка и цена явно обозначены как допущения эксперимента; без цены стоимости отсутствуют. Параметры live-сценария в этот эксперимент не переносятся. Товар с неполной недельной структурой остаётся доступен для выбора и показывает понятную ошибку: пропуски не заполняются нулями, демоданные не подставляются.

## Панель анализа

Рабочие функции прежнего `PurchaseApiPanel` перенесены в карточку товара `SkuDrawer`: детерминированный разбор, формула, предупреждения и текущие условия. Дополнительное текстовое объяснение использует существующий серверный `/api/agent`; без ключа доступен локальный разбор. Оно не меняет числа и не создаёт заказ.

Файлы друга `PurchaseApiPanel`, `PreviewBacktest`, `PreviewNavigation` и их CSS сохранены в репозитории как предыдущая реализация. Они не подключены к текущему основному экрану. Неподключённый макет API не добавлен в рабочую навигацию; его прежняя ссылка ведёт к рекомендациям и карточкам. Интеграционные тесты друга также сохранены.

## Проверка интерфейса

1. Открыть демо, найти `CAB-NYM-3X2.5`, открыть карточку и объяснение всплеска.
2. Изменить задержку в сценариях, применить её, проверить обновлённые рекомендации.
3. Выбрать допустимые позиции, создать черновик и скачать CSV. После изменения сценария убедиться, что черновик требует пересмотра.
4. Открыть проверку на истории, проверить источник и основной прогноз, выполнить сравнение и проигрывание.
5. Начать импорт с пустого экрана: выбрать CSV/XLSX, сопоставить поля, проверить ошибки и подтвердить. Импорт только продаж не разрешает закупочные действия.
6. Проверить переходы браузера и старые ссылки `#api`, `#orders`, `#start`; набор, поиск и применённый сценарий должны сохраниться.

Актуальные выполненные проверки и ограничения редизайна описаны в `REDESIGN_VERIFICATION.md`. Совместимость старых ссылок проверяется отдельно в `tests/navigation.test.ts`.

Новых зависимостей для интерфейса нет. Используются текущие зависимости основного приложения и независимый модуль `stockpilot-backtest/`.
