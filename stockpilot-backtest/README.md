# StockPilot AI — Проверка на прошлом

Независимое локальное приложение для честного сравнения обычного среднего и устойчивого прогноза на недельной истории. Нет сервера, БД, авторизации или API. Подготовлено для `BAITC-Hacks/hack-9b68f051-miras-and-dastan`: типы данных и версии React/Recharts/Zod совместимы, основной прогноз подключается через переданные функции. Автоматического изменения экранов и маршрутов партнёра нет.

## Запуск

Node.js 22.12+ (либо 20.19+) и npm:

```sh
npm install
npm run dev
```

Результат standalone-сборки: node_modules/.cache/stockpilot-backtest/dist (исключён из обхода исходников основного проекта).

## Архитектура

- `src/contracts.ts`: строгие типы и Zod-схемы всех публичных контрактов.
- `src/engine.ts`: чистая детерминированная симуляция; `simulate(input, strategy, name)` и `compareStrategies(input)`.
- `src/strategies.ts`: обычное среднее, устойчивая обработка и единая политика закупки.
- `src/adapter.ts`: пример преобразования канонических недельных продаж.
- `src/stockpilot.ts`: адаптер реального Dataset и внедрение функций основного прогноза.
- `src/BacktestPanel.tsx`: независимый React-компонент, стили в CSS Modules.
- `src/index.ts`: публичные экспорты UI; `src/core.ts`: чистый API без React/CSS. `main.tsx` и `standalone.css` принадлежат только оболочке.
- `data/demo/generate.ts`: фиксированный seed 20260923, шесть сценариев без коммерческих данных.
- `tests/*.checks.ts`: 25 проверок утечки, сроков, балансов, ограничений закупки, метрик, CSV и адаптера. Запускаются собственным vitest.config.mjs и не подхватываются автоматически тестовым runner основного проекта.

## Формулы

Используется вся доступная прошлая история, включая разогрев; скользящего окна нет. Наивный прогноз — арифметическое среднее. Стандартное отклонение — популяционное (делитель n).

Устойчивая стратегия при n < 5 использует обычное среднее. Иначе вычисляет медиану m, MAD = median(|x − m|), Q1 и Q3 с линейной интерполяцией. Верхняя граница = max(m + 3 × 1.4826 × MAD, Q3 + 1.5 × IQR, m + max(1, 0.5m)). Наблюдения выше границы заменяются медианой только в локальной копии для расчёта среднего и отклонения. Исходники не изменяются. Нули и нижние выбросы не удаляются. Порог заранее фиксирован, не оптимизируется по результатам теста. Этот способ подавляет верхние всплески, но не доказывает, что они были разовыми: начало роста может быть ошибочно подавлено.

L = ceil(leadTimeDays / 7), R = reviewPeriod, H = L + R.

Страховой запас SS = z × deviation × sqrt(H). Для уровней 50%, 90%, 95%, 99% используются z = 0, 1.281552, 1.644854, 2.326348. Это приближение нормального независимого спроса, не обещание достигнутого fill rate.

Целевой запас = forecast × H + SS. Потребность = целевой запас − текущий запас − открытые заказы. Если потребность ≤ 1e−9, заказ нулевой. Иначе заказ = ceil(max(потребность, MOQ) / packSize) × packSize. MOQ — нижняя граница, не отдельная кратность.

## Порядок событий

Для индекса недели i от startIndex до endIndex включительно:

1. Приходят все заказы с arrivesAt ≤ i.
2. В недели `(i − startIndex) % R === 0` формируется контекст только из `observations.slice(0, i)`, остатка после прихода, открытых заказов и одинаковых настроек.
3. Стратегия возвращает прогноз и отклонение, общая политика определяет заказ.
4. Заказ получает arrivesAt = i + L. При L = 0 он немедленно приходит до обработки спроса этой недели; иначе попадает в открытые поставки.
5. Обслуженный спрос = min(запас, фактический спрос недели). Остальной спрос потерян, без задолженности.
6. Фиксируются конечный запас, дефицит, заказ, приход и товар в пути.

Стратегии передаётся отдельная копия контекста, изменения этой копии не влияют на движок. Будущий спрос, аномалии и статистики полного ряда в контексте отсутствуют. Пользовательская функция обязана не замыкать внешнюю будущую историю самостоятельно. Никаких переобучений или подбора по будущему движок не выполняет.

## Метрики и ограничения

Fill rate = сумма отгрузок / сумма спроса, для нулевого спроса принят равным 100%. Средний запас — среднее конечных недельных остатков, не средний внутринедельный остаток. Максимальный запас учитывается после всех поступлений до спроса. Стоимость закупок = всё заказанное количество × себестоимость, в том числе заказы за границей периода. Стоимость среднего запаса = средний конечный запас × себестоимость; это оценка капитала, а не расходы на хранение. Без себестоимости денежные поля отсутствуют (в UI — «Нет себестоимости»). Конечный остаток и незавершённые поставки показаны отдельно; разница закупок не равна прибыли.

Продажи используются как приближение спроса. Скрытый спрос во время исторического дефицита неизвестен. Время внутри недели неизвестно, поэтому показываются недели с дефицитом, а не точные дни. Входной ряд должен содержать один SKU и непрерывные даты через семь дней; дубли, пропуски и отрицательные значения отклоняются. Начальный запас задаётся вручную, одинаковый для обеих стратегий; начальных поставок в пути нет. Текущий складской остаток партнёра автоматически не используется.

Не моделируются сезонность, тренд, сроки оплаты, бюджет, ограничения поставщика, возвраты и неопределённость поставок. Рост и сезонность в демо специально показывают ограничения; устойчивая стратегия вправе проиграть. Денежная единица демо — ₸. CSV UTF-8 BOM, разделитель `;`, кавычки экранируются, потенциальные формулы получают апостроф.

## Демонстрация на 60 секунд

1. 0–10 с: «Загрузить демо», оставить CAB-NYM-3X2.5. Начальная история — 20 недель; проверка — оставшиеся 32.
2. 10–25 с: «Запустить сравнение». Всплеск 180 ед. расположен на 27-й неделе полной истории (индекс 26). До этой недели он не влияет на решения; различие проявляется в последующих заказах.
3. 25–40 с: «В начало» → «Проиграть» или ползунок. Посмотреть заказ, приход, дефицит и прогноз обеих стратегий в журнале.
4. 40–50 с: изменить срок с 21 на 7 дней и повторить расчёт. Старые результаты сбрасываются при изменении настроек, чтобы не экспортировать устаревший результат.
5. 50–60 с: «Экспорт CSV», затем выбрать растущий спрос и показать, что преимущество не гарантировано.
